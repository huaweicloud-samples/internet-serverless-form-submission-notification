# 架构说明

## 总体架构

本实践演示「单个无服务器函数在一次请求内完成双写」的链路：网页表单通过公网接口提交 JSON，函数把同一份数据并行写入托管键值表并向通知主题发布消息，两条分支都完成后才返回统一响应。函数不保留任何长期密钥，也不需要管理服务器。

```
                         ┌────────────────┐
                         │   用户浏览器   │
                         │ 填写并提交表单 │
                         └─────────┬──────┘
                                   │ ① POST /submitForm（JSON）
                                   ▼
┌────────────────────────────────────────────────────────────────────┐
│                      APIG 专享版（公网入口）                       │
│            POST /submitForm · 跨域已开启 · 同步调用函数            │
└────────────────────────────────────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────┐
│              FunctionGraph  submit-form（Node.js 18）              │
│     解析表单 → Promise.all 并行双写 → 统一返回 200 / 400 / 500     │
└───────────┬─────────────────────────────────────┬──────────────────┘
            │ ②a 落库                               │ ②b 发布消息
            ▼                                     ▼
┌────────────────────────────┐    ┌──────────────────────────────────┐
│    GeminiDB 兼容键值表     │    │    SMN 主题 + 已确认邮件订阅     │
│    表 form_submissions     │    │     主题 New Form Submission     │
│ 主键 formId · VPC 内网 80  │    │     送达订阅时确认的收件邮箱     │
└────────────────────────────┘    └──────────────────────────────────┘
```

## 关键组件

| 组件 | 服务 | 职责 |
|---|---|---|
| 表单接口 | API 网关（APIG）专享版 | 对外提供 `POST /submitForm`，开启跨域，同步调用函数；API 需显式发布到 `RELEASE` 环境 |
| 提交函数 | 函数工作流（FunctionGraph） | Node.js 18 运行时；解析请求体，用 `Promise.all` 并行扇出到持久化与通知两条分支 |
| 键值存储 | 云数据库 GeminiDB（DynamoDB 兼容接口） | 存放表单记录，主键 `formId`；集群形态经负载均衡内网地址的高可用端口 80 访问 |
| 通知主题 | 消息通知服务（SMN） | 主题 + 已确认的邮件订阅；函数发布消息，平台负责投递 |
| 凭据来源 | 统一身份认证（IAM）云服务委托 | 以 `op_svc_cff` 为被委托服务，向函数下发临时凭据供控制面调用使用 |
| 网络 | 虚拟私有云（VPC）/ 子网 / 安全组 | 键值存储无公网端点，函数与网关实例均接入同一 VPC |
| 演示页面 | 静态 HTML | 收集表单字段，向表单接口发起跨域 POST |

## 工作流程

1. 浏览器把表单字段序列化为 JSON，`POST /submitForm`。
2. API 网关同步调用函数，传入代理事件（请求体位于 `event.body`）。
3. 函数解析请求体，得到表单对象；非法 JSON 返回 400。
4. 在同一个 tick 内启动两条分支：`Promise.all([发布通知, 写入记录])`。
5. 通知分支用函数上下文下发的临时凭据构建客户端，向主题发布以 `subject` 与 `message` 组成的消息；订阅者完成确认后收到邮件。
6. 持久化分支用实例账号 `rwuser` 与实例管理员密码连接兼容端点，写入 `formId`（随机十进制 ID）、`formData`（序列化后的原始表单）与 `created`（Unix 秒）。
7. 两条分支均成功时返回 200 与记录 ID；任一失败返回 500，错误信息写入函数日志。

## 两套凭据的分工

| 平面 | 目标 | 凭据 | 注入位置 |
|---|---|---|---|
| 数据面 | 键值存储兼容端点 | 实例账号 `rwuser` + 实例管理员密码 | `infra/functions.tf` 的 `user_data` |
| 控制面 | 通知主题发布接口 | 云服务委托下发的临时 Access Key / Secret Access Key / SecurityToken | 函数运行时的 `context` 对象，代码内读取 |

数据面不接受 IAM 委托凭据，也不接受临时凭据标识；控制面凭据不会出现在环境变量中，必须在函数内部从上下文读取。二者不可互换。

## 安全设计

| 项 | 设计 |
|---|---|
| 控制面凭据 | 由 IAM 云服务委托在运行时下发，平台自动轮换；代码包与配置中不含长期密钥 |
| 数据面凭据 | 实例管理员密码由部署参数提供，Terraform 标记为 `sensitive`；`terraform.tfvars` 被版本控制忽略 |
| 网络边界 | 键值存储不绑定公网地址，仅 VPC 内网可达；安全组只放通 VPC 网段的数据端口 |
| 接口鉴权 | 教学演示接口未启用访问鉴权；生产使用应在 API 网关上启用认证与限流，并把跨域来源从通配符改为具体站点 |
| 传输 | 对外表单接口使用 HTTPS；VPC 内的数据面连接使用 `http`（与实例 TLS 开关一致） |
| 响应缓存 | 提交响应显式设置 `Cache-Control: no-store` |
| 收件范围 | 邮件收件人由主题订阅决定，订阅须完成确认才会投递，函数无法任意指定收件地址 |

## 配置对应关系

| 配置项 | 位置 | 说明 |
|---|---|---|
| `GEMINIDB_ENDPOINT` | `infra/functions.tf` → `user_data` | 由实例负载均衡地址与端口 80 推导，可用 `geminidb_endpoint_override` 覆盖 |
| `FORM_TABLE` | `infra/variables.tf` → `form_table_name` | 表单记录表名；首次写入时由函数探测并按需创建 |
| `SMN_TOPIC_URN` | `infra/messaging.tf` → 主题 ID | 函数发布消息的目标主题 |
| `notify_email` | `infra/variables.tf` | 为空则不创建邮件订阅；非空时须在邮箱中确认订阅 |
| `cors` | `infra/apig.tf` | 网关侧跨域开关；前端页面同时携带 JSON 请求头 |
| `enable_public_api` | `infra/variables.tf` | 是否创建网关专享实例与公网入口，默认 `true` |

## 轻量验证档拓扑

把 `enable_public_api` 设为 `false` 时，网关实例、分组、API 与发布动作均不创建；VPC、键值存储、通知主题与函数保持不变。链路变化只在「谁去触发函数」这一环，函数内的并行双写完全一致。

```
                         ┌────────────────┐
                         │  直接调用函数  │
                         │ （控制台/CLI） │
                         └─────────┬──────┘
                                   │ ① 传入表单 JSON
                                   ▼
┌────────────────────────────────────────────────────────────────────┐
│              FunctionGraph  submit-form（Node.js 18）              │
│     解析表单 → Promise.all 并行双写 → 统一返回 200 / 400 / 500     │
└───────────┬─────────────────────────────────────┬──────────────────┘
            │ ②a 落库                               │ ②b 发布消息
            ▼                                     ▼
┌────────────────────────────┐    ┌──────────────────────────────────┐
│    GeminiDB 兼容键值表     │    │    SMN 主题 + 已确认邮件订阅     │
│    表 form_submissions     │    │     主题 New Form Submission     │
│ 主键 formId · VPC 内网 80  │    │     送达订阅时确认的收件邮箱     │
└────────────────────────────┘    └──────────────────────────────────┘
```

两档的判废条件相同：只要仍由单个函数在一次请求内并行完成持久化与真实消息发布，主题即成立。差别在于轻量档没有对外表单接口，验证证据不含公网入口调用，浏览器演示页也无法使用。
